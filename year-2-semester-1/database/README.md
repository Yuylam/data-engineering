## Project
The project in this subject continues the project from the subject [System Analysis and Design](/year-1-semester-2/system-analysis-and-design/) of the previous semester. Combined with [Software Engineering](/year-2-semester-1/software-engineering/) and [System Development Technology](/year-2-semester-1/system-development-technology/), the complete system is developed.

In this course, the database of the system is designed and implemented.

### [Phase 1 Proposal](/year-2-semester-1/database/project-phase1-proposal.pdf)
In the first phase the existing system is examined and the core modules of the proposed solution is determined.

### [Phase 2 Conceptual Database Design](/year-2-semester-1/database/project-phase2-conceptual-database-design.pdf)
In this phase, we focus on developing the Entity-Relationship Diagram (ERD) for the system, starting from individual modules and combining them into a global ERD for the entire system.

### [Phase 3 Logical Database Design](/year-2-semester-1/database/project-phase3-logical-database-design.pdf)
In this phase, the logical database design is created through normalisation of the ERD created in the previous phase. This phase transforms the conceptual model into a structure that can be directly mapped to a physical database, ensuring data integrity and normalisation.

### [Lab Assignment DDL & DML](/year-2-semester-1/database/lab-assignment-ddl-dml.pdf)
This assignment focuses on designing and implementing the database for the Admin Updating Module. It covers creating tables (DDL) and performing operations such as inserting, updating, retrieving, and deleting data (DML) for policies, banners, and transactions.

### [Alternative Assessment Phase 1 Proposal for New Module to be Implemented & Database Design](/year-2-semester-1/database/alternative-assessment-phase1.pdf)
On top of the initial system, this assignment requires us to identify weakness and suggest improvements for the system. 

### [Alternative Assessment Phase 2 SQL and Inteface Implementation](/year-2-semester-1/database/alternative-assessment-phase2.pdf)
Implementation of SQL code according to the proposed improvements.

## Reflection
This course guides us to build a database step by step. With the database unified in the first place, there are no integration issues when we work on the development. Since development involved multiple members, we coordinated updates to entities and attributes to keep everyone in sync.
